# CLAUDE.md — PSA Certificate Generator

Offline browser app that batch-generates **training / event certificates** for
PSA Marinduque (Philippine Statistics Authority, Provincial Statistical
Office). Sibling of `psa-id-generator` and `psa-payslip-generator`, built the
same way on purpose. The user is PSA office staff, not a developer — explain
things plainly, keep it zero-install.

Started September 2026 from a scan of the office's existing Canva certificate
(a Certificate of Participation for a CBMS/PSIC capacity-building run).

## Hard constraints (agreed with user)

- **Fully offline, no server, no login.** Runs by double-clicking `index.html`
  in Edge/Chrome (`file://` origin — no `fetch()` of local files; that's why
  artwork is base64 in `assets.js` and libraries load via script tags).
- **Sizes: A4 (210 × 297 mm) or half of A4 / A5 (148 × 210 mm)**, each in
  **portrait or landscape** — four page shapes, all first-class.
- **A5 can be imposed 2-up on one A4 sheet** (`batch.sheet = 'a4'`), with a
  dotted cut line. Two A5 portraits sit side by side on A4 landscape; two A5
  landscapes stack on A4 portrait. Both fit exactly (2 × 148 = 296 ≈ 297). The
  office only stocks A4, so this is how an A5 certificate actually gets
  printed.
- **Dynamic per batch:** certificate title, event/training title, hours, type
  of training, date range, venue, date issued, and every small connector line.
  **Dynamic per person:** name, plus an optional **Role** that replaces the
  "for actively participating in the" line — so speakers, facilitators and
  participants can come out of one run.
- The signature line prints **blank on purpose**; `settings.sigEnabled` is off
  by default. Unlike the ID generator there is no bundled official signature
  and therefore no password gate — there is nothing pre-loaded to protect.

## Architecture (no build step, vanilla JS)

- `index.html` / `style.css` / `app.js` — UI in three steps: who gets a
  certificate (Excel import via SheetJS + column mapping + manual add + roster
  with include-checkboxes and ⚠ for blank/duplicate names), certificate details
  (with live previews of the composed "for 24 hours…" and "Given this 17th…"
  lines, and eye toggles that hide optional lines), then size/design (size,
  orientation, paper, corner design, colours, lettering, up to three logos).
  Auto-regenerates the preview 450 ms after any change. A change that lands
  while a batch is still building is remembered (`regenPending`) and re-run when
  that finishes — 200 certificates in Trajan take ~2 s, comfortably longer than
  the debounce, and such changes used to be dropped, leaving a stale preview.
  Errors also surface as a **toast** at the top of the window, because the
  status line sits at the bottom of step 3, scrolled out of sight while you work
  in step 1. An open `<dialog>` is in the browser's top layer and would paint
  over a toast attached to `<body>`, so `showToast` appends it to the open
  dialog instead.
- `core.js` — **the engine**. UMD: `PSACert` in the browser, `require`-able in
  Node (that's how the headless tests work). Holds `LAYOUT`, `DEFAULT_BATCH`,
  `DEFAULT_SETTINGS`, `TITLE_PRESETS`/`FOR_LINES`, `autoMap`, `sheetPlan`,
  `formatDateRange`, `hoursLine`, and `generatePdf` (pdf-lib).
- `assets.js` — generated by `tools/build-assets.js` from `assets/logos/`.
  Exposes `PSA_ASSETS` = `[{key,name,dataUri}]`. **Never edit by hand.** Drop a
  PNG/JPG into `assets/logos/` (the file name becomes the label in the app) and
  re-run `node tools/build-assets.js`. Currently: the PSA seal, lifted from
  `psa-inventory/public/img/psa-logo.png` and downscaled to 800 px.
- `lib/` — pinned offline copies, copied from `psa-id-generator`:
  `xlsx.full.min.js` (SheetJS 0.20.3), `pdf-lib.min.js` (1.17.1),
  `fontkit.umd.min.js`, `cinzel-font.js` / `cinzel-bold-font.js`
  (→ `PSA_FONT_CINZEL` / `PSA_FONT_CINZEL_BOLD`), `Cinzel-OFL.txt`.
  **None of these are in `index.html`.** They were, and the 2.8 MB had to
  download and parse before `app.js` ran, so the form was dead until all of it
  landed. `app.js` now injects them as script tags when they are wanted
  (`loadScript` / `ensureXlsx` / `ensurePdfLib` / `ensureTrajan`): the page
  itself is ~370 KB, pdf-lib and SheetJS start loading the moment the form is up
  (`warmUp`, so they are in hand before anyone needs them), and fontkit + the
  two Cinzel files — 964 KB for a style most batches never use — only load if
  Trajan is actually chosen. **Injected script tags, not `fetch()`**: on
  `file://` fetch and XHR are blocked for local files, script tags are not.
  `tools/build-dist.js` copies `lib/` by name, so dynamic loading does not
  change what gets deployed.
- **Fonts.** The default "Classic serif" lettering is pdf-lib's built-in
  **Times** family — no embedding, and it matches the office's original.
  "Trajan style" swaps the title, the recipient name and the signatory names to
  **Cinzel** (open SIL-OFL Trajan look-alike), which needs fontkit:
  `doc.registerFontkit(opts.fontkit)` then
  `doc.embedFont(opts.displayFontBytes, { subset: true })`. `app.js` fetches the
  Cinzel files only when that style is selected, and waits for them before
  building the PDF. Without them the engine falls back to Times bold rather than
  failing — which is also what happens if the fetch fails, so fonts that will
  not load cost the lettering, not the batch.
  Checking whether a PDF really embedded them by searching the bytes for
  "Cinzel" does **not** work: pdf-lib writes object streams, so the font names
  sit inside compressed data — a classic-serif PDF contains no "Times" either.
  The subset shows up plainly in the file size instead (~5 KB), which is how
  `tools/uitest-driver.js` checks it.

### The layout engine (the part worth understanding)

The ID generator pins every element to a fraction of one fixed card. That
cannot work here: A4 portrait and A5 landscape have opposite aspect ratios. So:

- **Everything is sized against `u` = the page's shorter side.** A4 landscape
  therefore gets the same type sizes as A4 portrait, and A5 is the same design
  at ~70%.
- **Vertical position is flowed, not fixed.** `buildFlow` measures each block
  (preamble, title, presented-to, name, for-line, event, hours+dates, venue,
  given-date, signatures), stacks them with their gaps, and returns a height.
  `drawCertificate` shrinks a global `scale` by 2% at a time until the stack
  fits between the logo row and the bottom margin — re-measuring each pass,
  because wrapping changes with size.
- **Leftover room goes into the gaps first** (`LAYOUT.gapGrow`, up to +45%),
  then `LAYOUT.topBias` (0.30) puts most of what's still left *below* the
  block, which is what keeps the text high on the page like the original.
- **The title and the name shrink to fit one line before they wrap**
  (`fit`/`fitFloor` in `LAYOUT`). This is what absorbs Cinzel being much wider
  than Times — without it, "Certificate of Participation" wraps in Trajan style.
- `givenRuns` returns the "Given this 17th day of…" line as *runs* so the
  ordinal suffix can be drawn smaller and raised, like the original.

### The corner artwork

Redrawn as **vector polygons**, not extracted raster — the original is a Canva
export we do not have, and vectors scale to any size/orientation and recolour
from one accent. `drawFrame` uses `page.drawSvgPath` with the origin at the
certificate's **top-left** (drawSvgPath's +y runs down, unlike pdf-lib's usual
bottom-left origin). Coordinates are in `u` units measured in from whichever
corner each shape hangs off. The white slivers that separate the facets are
literally drawn in white over the dark shapes — fine, because the ground is
white.

Depths are deliberately asymmetric: the top-right mass dominates and everything
else is an accent, so the centred text column always has white either side.
**If you make the top-right shapes deeper than ~0.32u, they collide with the
certificate title** — that was checked by rasterizing and looking.

## localStorage, not IndexedDB (important)

The logo library is `bundled artwork (assets.js) + user uploads (localStorage)`.

**Do not "improve" this to IndexedDB.** On a `file://` origin in Edge/Chrome,
`indexedDB.open()` never completes — no `success`, no `error`, no `blocked`;
the request sits at `readyState: "pending"` forever, so even a `.catch()`
fallback never runs and the logo list silently stays empty. This was measured
here with a probe page, with and without `--allow-file-access-from-files`. The
ID generator's IndexedDB logo library has the same latent problem and is
probably only ever exercised over https on the deployed site.

Uploads are shrunk to 700 px before storing, which keeps them well inside the
~5 MB localStorage budget; a quota failure surfaces as a plain message rather
than a silent loss. Bundled logos cannot be deleted from the library.

Also persisted: `settings` and the certificate `batch` in localStorage, column
mappings keyed by header row, and the hand-typed people (`psa-cert-people`).
All per-browser, per-machine — Backup/Restore (JSON, `version: 1`) is how it
travels.

**The people are deliberately not in the backup.** A backup carries your setup —
signatories, logos, wording — and restoring one on another machine should not
drop someone else's roster into your list. They are persisted only so a reload
does not cost you twenty retyped names.

The roster edits in place (`editableCell`, `contentEditable = 'plaintext-only'`
with a fallback for engines that reject that value). Whitespace is collapsed on
the way into the model, because a pasted line break would wrap a name across two
lines on the certificate. Warnings are re-flagged by `refreshWarnings`, which
walks the existing rows rather than rebuilding the table — a rebuild mid-edit
takes the caret with it. `batch.sortNames` (the A → Z button) is a batch
property, not a view setting: `displayPeople` feeds both the table and
`chosenPeople`, so what you see is the order the certificates print in.

## Verify loop (do this after any layout/engine change)

```
node tools/test-generate.js                      # 7 variants -> out/*.pdf
node tools/raster.mjs out/a4-portrait.pdf out/r 1100
# then look at the PNGs with the Read tool
```

`npm i` once per machine for `mupdf` (WASM, no native deps) and `jimp`. The
Read tool **cannot rasterize PDFs on this machine** (no pdftoppm) — use
`tools/raster.mjs`. Node 24 is installed; Python is NOT.

For the UI (catches wiring bugs the engine tests never touch):

```
node tools/uitest.js        # writes _uitest.html = index.html + the driver
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless=new \
  --disable-gpu --no-sandbox --virtual-time-budget=90000 \
  --dump-dom "file:///.../_uitest.html"        # read the #diag block
```

Launching Edge needs `dangerouslyDisableSandbox` on the Bash/PowerShell call —
it is otherwise blocked and exits silently with no output at all. The driver
(`tools/uitest-driver.js`) fills the form, adds people, and walks every
size/orientation/paper/lettering combination, reporting into `#diag`. **Blank
the status line before waiting on a regeneration** — the previous run's message
is still there and a naive poll returns immediately (this produced a false
"2 sheets" reading once).

Edge's PDF viewer does not render inside the iframe in headless mode, so the
preview pane is blank in screenshots. That is not a bug.

## Excel contract

Headers `Full Name | Role`. Only the name matters; `autoMap` fuzzy-matches and
falls back to column 1 for the name if nothing matches.

**The heading row is searched for, not assumed to be row 1** (`findHeaderRow`).
Assuming row 1 quietly ate a person: a sheet opening with a merged title like
"Certificate Participants List" had that title read as the headings — and since
it contains "participants", `autoMap` matched it — so the real `Full Name`
heading became the first certificate. A bare list with no headings lost its
first name the same way; that case now returns `index: -1` with generic
`Column N` labels and treats every row as a person. Only the first 5 rows are
scanned, a heading cell must be ≤ 24 characters (a sentence is a title, not a
heading), and ties go to the LAST row, because a title sits above the headings.

**SheetJS never refuses a file.** Handed a PDF, a .docx or a photo it reads the
bytes as delimited text and returns "rows", which used to become a roster of
binary gibberish. Two gates: `loadFile` rejects by extension (the drop zone
bypasses the input's `accept`), and `core.looksBinary` rejects rows carrying
control characters for anything that gets past the name.

The app has a "Download Excel template" button, and `node tools/make-sample.js`
writes `sample-participants.xlsx`.

`tools/uitest-driver.js` builds real .xlsx files in the page and drops them on
the drop zone, so all of this is covered by the headless UI run.

## Open items / watch-outs

- The office's **Bagong Pilipinas** logo sits beside the PSA seal on the real
  certificate but is not in this repo. The user adds it once via **+ Add**
  (it persists on that machine) — or drop the PNG into `assets/logos/` and
  re-run `node tools/build-assets.js` to bundle it for everyone.
- The corner artwork is a **redraw in the same spirit**, not a pixel copy of
  the Canva original. Tune it by editing the polygons in `drawFrame`, then
  rasterize and look.
- Advise printing at **Actual size / 100%** — "fit to page" shrinks it.
- No real-world print test has been done yet (as of 16 September 2026),
  including the A5 2-up cut.
## Deployment

Live at <https://psa-certificate-generator.netlify.app> (Netlify site
`psa-certificate-generator`, account `axellexious`), built from
`JosueJamesAllen/psa-certificate-generator` on `main` via
`node tools/build-dist.js` → `dist/`. Same shape as `psaidgenerator`.

The site was created through the Netlify API rather than the web UI, which does
**not** set up repo access on its own — the first build failed with
"Host key verification failed". Fixing it took three extra steps, worth knowing
if a site is ever recreated this way: create a deploy key
(`POST /api/v1/deploy_keys`), add its `public_key` to the GitHub repo
(`POST /repos/:owner/:repo/keys`, read-only), then PATCH the site's `repo`
object with `deploy_key_id`. A push webhook to
`https://api.netlify.com/hooks/github` also has to be added to the repo by hand
(`POST /repos/:owner/:repo/hooks`, events `push`/`pull_request`/`delete`);
without it nothing rebuilds on push. Both were done and auto-deploy is verified
working.

Deploying changes nothing about how the app works — it stays a static,
offline-capable page, and `file://` is still the primary way the office runs it.
Note that the localStorage/IndexedDB distinction above still matters: over https
IndexedDB *would* work, but the app must keep working from `file://`, so the
localStorage store stays.
